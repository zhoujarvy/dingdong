# 叮咚生产部署说明（Nginx + NSSM）

> 目标拓扑：**Nginx（80 端口，静态托管 + 反向代理）→ FastAPI/uvicorn（127.0.0.1:8000，NSSM 守护的 Windows 服务）**
>
> 以下以 Windows 服务器、部署目录 `D:\dingdong` 为例。
>
> 内网离线部署请看 [离线部署教程.md](离线部署教程.md)。

## 1. 服务端准备

```bat
:: 假设项目已复制到 D:\dingdong（server / web / client / docs / deploy）
cd /d D:\dingdong\server

:: 创建 Python 3.8 虚拟环境并安装依赖
py -3.8 -m venv venv
venv\Scripts\pip install -r requirements.txt

:: 修改管理密码（务必）
notepad config.json

:: 试运行确认正常（Ctrl+C 退出）
venv\Scripts\python run.py
```

> 提示：管理后台（web/）如需重新构建：`cd web && npm install && npm run build`，
> 产物自动输出到 `server\static\`。官网（`web\site.html`）随管理后台一起构建。

## 2. NSSM：把后端注册为 Windows 服务

1. 从 <https://nssm.cc/download> 下载 nssm.exe（win64），放到 `deploy\` 目录或加入 PATH。
2. 运行管理脚本（或逐条执行其中的命令）：

```bat
cd /d D:\dingdong\deploy
service.bat install     :: 安装并启动服务（开机自启）
service.bat restart     :: 更新代码后重启
service.bat uninstall   :: 卸载
```

3. 验证：

```bat
nssm status DingDongServer
curl http://127.0.0.1:8000/api/health
```

要点（脚本已内置）：
- `AppDirectory` 设为 `D:\dingdong\server`，数据库 `dingdong.db` 落在该目录
- 日志输出到 `server\logs\`，单文件 5MB 自动轮转
- 崩溃自动拉起、随系统自启动

## 3. Nginx：静态托管 + 反向代理

1. 安装 Nginx for Windows（解压即用），例如 `C:\nginx`。
2. 将 `deploy\nginx-dingdong.conf` 复制到 `C:\nginx\conf\conf.d\`（并在 `nginx.conf` 的 `http{}` 中确认有 `include conf.d/*.conf;`），按需修改其中的路径与 `server_name`。
3. 启动 / 重载：

```bat
cd /d C:\nginx
start nginx
nginx -s reload    :: 改配置后重载
```

4. 防火墙放行 80 端口（客户端与浏览器都走这里）：

```powershell
netsh advfirewall firewall add rule name="DingDong 80" dir=in action=allow protocol=TCP localport=80
```

反向代理已包含 WebSocket 升级头与 300 秒读超时（大于客户端 30 秒心跳周期），`/ws` 长连接可稳定穿透。

## 4. 客户端与日常运维

- 客户端安装包：本机执行 `client\make_installer.bat`，产物自动进入 `server\downloads\DingDongSetup.exe`（官网下载按钮即指向它），并把版本号写入 `version.txt` 供官网展示。
- 客户端注册时服务器地址填 `http://服务器IP`（80 端口，无需带 :8000）。
- 数据备份：定期复制 `server\dingdong.db`（建议先停服务或用 `sqlite3 .backup`）。
- 升级流程：更新代码 → `service.bat restart` → 前端有改动再 `npm run build`。

## 5. 常见问题

| 现象 | 处理 |
|------|------|
| 服务起不来 | `nssm dump DingDongServer` 看配置；查看 `server\logs\error.log`；确认 venv 路径正确 |
| WS 连不上 | Nginx 是否加载了带 Upgrade 头的配置；`proxy_read_timeout` 是否过短 |
| 官网能开但 404 | 检查 `server\site\index.html` 是否存在、Nginx alias 路径结尾的斜杠 |
| 8000 被占用 | 改 `config.json` 的 `port`，同时改 Nginx 反代目标端口 |
