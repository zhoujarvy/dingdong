# 叮咚消息推送系统 · 第三方接入文档

> 本文档面向需要向 Windows 终端推送消息的第三方程序开发者。阅读本文档即可完成接入，无需了解系统内部实现。

## 1. 系统简介

「叮咚」是一套通用消息推送系统，由三部分组成：

```
┌──────────────┐   POST /api/messages    ┌──────────────┐   WebSocket   ┌──────────────┐
│  你的程序     │ ──────────────────────> │  叮咚服务器   │ ────────────> │ Windows 客户端│
│ (第三方发送方) │      携带 X-API-Key      │  + 管理后台   │   实时推送     │  (系统托盘)   │
└──────────────┘                         └──────────────┘               └──────────────┘
```

- 消息推送给终端后，客户端立即弹窗提醒（提示音 / 语音朗读 / 右下角弹窗）
- 用户点击弹窗打开**网页消息中心**查看全文，支持已读/未读、删除、按时间分组
- 终端不在线时消息自动保存，上线后立即补发

## 2. 核心概念

| 概念 | 说明 |
|------|------|
| **终端（Terminal）** | 一台安装了叮咚客户端的 Windows 电脑。客户端注册时只需提供一个名称，服务器返回唯一的 **6 位终端编码**（大写字母 + 数字，如 `A2B3C4`） |
| **API Key** | 第三方程序调用推送接口的凭证，格式为 `dd_` + 32 位十六进制（如 `dd_3f2a...`）。由服务器管理员在管理后台「API 密钥」页创建，可随时吊销 |
| **消息（Message）** | 包含标题、内容、发送方三部分内容，推送到指定终端编码 |

> **如何获得接入凭据？**
> 1. 向叮咚服务器管理员申请一个 API Key
> 2. 告知消息需要送达的终端编码（由终端使用者在客户端上注册后提供，可在客户端主界面或管理后台「终端管理」页查到）

## 3. 推送接口

### POST /api/messages

#### 请求头

| 名称 | 必填 | 说明 |
|------|------|------|
| `Content-Type` | 是 | `application/json` |
| `X-API-Key` | 是 | 管理员分配的 API Key |

#### 请求体

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `terminal_code` | string | 与 terminal_codes 二选一 | 单个终端编码，如 `"A2B3C4"` |
| `terminal_codes` | string[] | 与 terminal_code 二选一 | 终端编码数组，**一条消息群发多个终端**，如 `["A2B3C4","X9Y8Z7"]` |
| `title` | string | 是 | 消息标题，1–200 字 |
| `content` | string | 否 | 消息内容，最长 20000 字，支持多行文本；其中的 URL（http/https）会在消息中心与全文页自动转为可点击链接 |
| `sender` | string | 否 | 发送方名称（默认 `未命名`），建议填写你的系统名，如 `"OA系统"` |

#### 响应（HTTP 200）

```json
{
  "total": 2,
  "delivered": 1,
  "results": [
    { "terminal_code": "A2B3C4", "message_id": 101, "delivered": true,  "error": null },
    { "terminal_code": "X9Y8Z7", "message_id": 102, "delivered": false, "error": "终端不在线，已入库等待补发" }
  ]
}
```

- `delivered: true` —— 终端在线，已实时送达
- `delivered: false` 且 error 为「已入库等待补发」—— 终端离线，消息已保存，终端上线后自动送达（**无需重发**）
- `message_id` 不为空 —— 消息已入库，可用于与管理后台对账

#### 错误码

| HTTP 状态 | 说明 | 处理建议 |
|-----------|------|----------|
| 200 | 成功（个别终端失败见 results 内 error） | - |
| 400 | 未指定接收终端编码 | 检查 terminal_code(s) 字段 |
| 401 | 缺少 X-API-Key 请求头 | 补充请求头 |
| 403 | API Key 无效或已被吊销 | 联系管理员确认密钥 |
| 422 | 参数校验失败（如 title 为空、超长） | 检查字段长度与类型 |

### GET /api/terminals/{code}

查询终端信息：**凭唯一编码获取终端名称与状态**，适合在发送前校验终端是否有效、或同步终端档案。

#### 请求头

| 名称 | 必填 | 说明 |
|------|------|------|
| `X-API-Key` | 是 | 管理员分配的 API Key |

路径参数 `code` 为 6 位终端编码，大小写不敏感。

#### 响应（HTTP 200）

```json
{
  "code": "A2B3C4",
  "name": "前台收银机",
  "status": "active",
  "last_seen_at": "2026-09-23 10:00:00",
  "online": true
}
```

| 字段 | 说明 |
|------|------|
| `status` | `active` 有效 / `revoked` 已注销（注销后推送会返回「终端不存在或已注销」） |
| `last_seen_at` | 最近一次连接时间 |
| `online` | 当前是否有客户端在线（同码多台电脑在线亦为 true） |

#### 错误码

| HTTP 状态 | 说明 | 处理建议 |
|-----------|------|----------|
| 401 | 缺少 X-API-Key 请求头 | 补充请求头 |
| 403 | API Key 无效或已被吊销 | 联系管理员确认密钥 |
| 404 | 终端编码不存在 | 核对编码；注意已注销终端仍可查询到（status=revoked） |

### GET /api/health

健康检查，无需鉴权，返回 `{"status": "ok"}`。

## 4. 调用示例

### curl

```bash
# 单发
curl -X POST http://服务器IP:8000/api/messages \
  -H "Content-Type: application/json" \
  -H "X-API-Key: dd_你的密钥" \
  -d '{
    "terminal_code": "A2B3C4",
    "title": "工单提醒",
    "content": "您有一条新的紧急工单，请及时处理。",
    "sender": "OA系统"
  }'

# 群发（一条消息发给多个终端）
curl -X POST http://服务器IP:8000/api/messages \
  -H "Content-Type: application/json" \
  -H "X-API-Key: dd_你的密钥" \
  -d '{
    "terminal_codes": ["A2B3C4", "X9Y8Z7", "QW3E4R"],
    "title": "系统维护通知",
    "content": "今晚 22:00-24:00 系统升级维护，请提前保存工作。",
    "sender": "运维平台"
  }'

# 查询终端名称与状态
curl http://服务器IP:8000/api/terminals/A2B3C4 \
  -H "X-API-Key: dd_你的密钥"
```

### Python (requests)

```python
import requests

SERVER = "http://服务器IP:8000"
API_KEY = "dd_你的密钥"

def push(title, content, sender, codes):
    """codes: 终端编码列表，如 ["A2B3C4"] 或 ["A2B3C4", "X9Y8Z7"]"""
    resp = requests.post(
        f"{SERVER}/api/messages",
        headers={"X-API-Key": API_KEY},
        json={
            "terminal_codes": codes,
            "title": title,
            "content": content,
            "sender": sender,
        },
        timeout=10,
    )
    resp.raise_for_status()
    return resp.json()

result = push("工单提醒", "您有一条新的紧急工单，请及时处理。", "OA系统", ["A2B3C4"])
print(result["results"])
```

### C# (.NET Framework 4.8 / .NET 6+)

```csharp
using System;
using System.Collections.Generic;
using System.Net.Http;
using System.Text;
using System.Threading.Tasks;

public static class DingDong
{
    private const string Server = "http://服务器IP:8000";
    private const string ApiKey = "dd_你的密钥";
    private static readonly HttpClient Http = new HttpClient();

    public static async Task<string> PushAsync(string title, string content,
        string sender, params string[] terminalCodes)
    {
        var body = "{\"terminal_codes\":" + Json(terminalCodes) +
                   ",\"title\":" + Json(title) +
                   ",\"content\":" + Json(content) +
                   ",\"sender\":" + Json(sender) + "}";
        var req = new HttpRequestMessage(HttpMethod.Post, Server + "/api/messages")
        {
            Content = new StringContent(body, Encoding.UTF8, "application/json")
        };
        req.Headers.Add("X-API-Key", ApiKey);
        var resp = await Http.SendAsync(req);
        resp.EnsureSuccessStatusCode();
        return await resp.Content.ReadAsStringAsync();
    }

    // 极简 JSON 转义，生产环境建议使用 Newtonsoft.Json / System.Text.Json
    private static string Json(string[] a)
        => "[" + string.Join(",", a.ConvertAll(s => "\"" + s + "\"")) + "]";
    private static string Json(string s)
        => "\"" + (s ?? "").Replace("\\", "\\\\").Replace("\"", "\\\"")
                          .Replace("\n", "\\n").Replace("\r", "") + "\"";
}
```

## 5. 消息生命周期

| 时间字段 | 含义 |
|----------|------|
| `created_at` | 你的程序调用接口的时间 |
| `pushed_at` | 消息实际送达终端的时间（离线补发时为补发时间） |
| `read_at`   | 用户在消息中心点开该消息的时间 |

用户可在消息中心删除消息（删除后不再显示给用户，管理后台仍保留记录用于审计）。

## 6. 注意事项与最佳实践

1. **API Key 保密**：Key 等同于推送权限，请勿写入前端代码或提交到代码仓库；泄露后联系管理员吊销。
2. **离线消息自动补发**：`delivered: false` 不代表失败，无需定时重发同一消息，会造成重复提醒。
3. **终端编码变更**：终端重装系统/重新注册后编码会变化，建议将终端编码配置化，不要硬编码。
4. **终端注销规则**：终端超过 30 天未连接服务器会被自动注销，向已注销终端推送会返回 `终端不存在或已注销`，此时应提醒相关人员重新注册。
5. **群发数量**：单次请求建议不超过 100 个终端编码；更多终端可分批调用。
6. **标题即摘要**：弹窗与语音朗读优先展示标题，建议标题包含关键信息（如「【紧急】XX工单待处理」）。
7. **内容格式**：`content` 为纯文本，换行符 `\n` 会在消息中心按原样显示，不支持 HTML/Markdown。
8. **消息去重**：接口层不做幂等去重，重复调用会产生重复消息；如需去重请调用方自行保证。

## 7. 常见问题（FAQ）

**Q：推送成功但用户没看到弹窗？**
A：确认客户端正在运行（系统托盘有叮咚图标）；离线补发的消息也会弹窗，但如果弹窗出现时用户不在电脑前，可打开网页消息中心查看全部历史消息（含已读/未读状态）。

**Q：同一台电脑能注册多个终端吗？**
A：可以，但通常一台电脑一个终端即可。同一终端编码重复连接时，旧连接会被新连接替换。

**Q：如何知道某条消息用户是否已读？**
A：第三方接口暂不提供回查，可请管理员在管理后台「消息记录」页查看（含送达时间、阅读时间、删除状态）。

**Q：能定时/延时发送吗？**
A：暂不支持，请在你自己的程序中用定时任务触发调用。
