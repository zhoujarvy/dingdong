## 1. 系统概述与架构

叮咚是一套自托管的通用消息推送系统：第三方业务程序通过 HTTP 接口投递消息，服务器经 WebSocket 实时送达 Windows 客户端；用户在**网页消息中心**统一查看、已读、删除消息。

```
                         ┌────────────────────────────────────────────────┐
                         │                叮咚服务器 (FastAPI)              │
   第三方程序 ──POST /api/messages (X-API-Key)──> routes_public ──┐        │
                         │                                        │        │
   管理后台(Vue3) ──/api/admin/* (Bearer)──> routes_admin          │ ws.py │
                         │                                        │ 推送   │
   网页消息中心 ──/t/{code} + /api/inbox/*──> page_inbox ─────────┤        │
                         │                                        ▼        │
                         │            SQLite (terminals/messages/api_keys) │
                         │                                        ▲        │
   Windows 客户端 ◀──────────── WebSocket /ws/{code} 长连接 ────────────────┘
   (托盘提醒)                (心跳 / 实时推送 / 离线补发 / 未读同步)
```

**关键机制**

| 机制 | 说明 |
|------|------|
| 实时推送 | 客户端与服务器保持 WebSocket 长连接，30 秒心跳；消息入库后立即经连接下发并记录 `pushed_at` |
| 离线补发 | 终端不在线时消息仅入库；连接建立后服务器补发全部**未删除**消息（`pushed_at` 补记） |
| 未读同步 | 网页消息中心的已读/删除操作会实时向在线客户端推送 `unread` 消息，驱动托盘角标 |
| 自动注销 | 后台任务每小时检查，`last_seen_at` 超过 30 天（可配）的终端自动置为 `revoked` |
| 多端并存 | 同一终端编码允许多条连接并存（多台电脑同时登录），推送广播给全部在线连接 |

**技术栈**：服务端 Python 3.8 + FastAPI + uvicorn + SQLite（WAL）；管理后台 Vue 3 + Element Plus + Vite；客户端 C# WPF（.NET 6 自包含发布，仅 System.Speech 一个 NuGet 依赖）；打包 Inno Setup 6；生产部署 Nginx + NSSM。

## 3. 数据库设计

SQLite 单库（默认 `server/dingdong.db`，WAL 模式），三张表。时间字段统一为本地时间字符串 `YYYY-MM-DD HH:MM:SS`。

### terminals（终端）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增主键 |
| code | TEXT UNIQUE | 6 位终端编码（字符集去掉易混淆的 0/O/1/I，随机生成、查库去重） |
| name | TEXT | 终端名称 |
| created_at | TEXT | 注册时间 |
| last_seen_at | TEXT | 最近一次连接/心跳时间（注册时初始化为注册时间） |
| status | TEXT | `active` / `revoked` |
| revoked_at | TEXT | 注销时间 |
| revoke_reason | TEXT | 注销原因（手动注销 / 超过30天未连接，自动注销 / 客户端主动注销） |
| inbox_token | TEXT | 网页消息中心访问令牌（32 位 hex，注册时生成；旧库由 init_db 迁移补齐） |

### messages（消息）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 消息 ID |
| terminal_id | INTEGER FK→terminals | 所属终端 |
| title / content / sender | TEXT | 标题（≤200）/ 内容（≤20000，纯文本）/ 发送方 |
| access_token | TEXT | 单条消息全文页 `/m/{id}` 的访问令牌（32 位 hex） |
| created_at | TEXT | 接口收到的时间 |
| pushed_at | TEXT | 经 WebSocket 送达时间；NULL=未送达（等待补发） |
| read_at | TEXT | 首次阅读时间；NULL=未读 |
| deleted_at | TEXT | 客户端/消息中心删除时间（软删除）；NULL=未删 |

索引：`idx_messages_terminal(terminal_id, deleted_at, id)` 支撑收件箱查询。

### api_keys（推送密钥）

| 字段 | 类型 | 说明 |
|------|------|------|
| id / name | PK / TEXT | 密钥名称（调用方） |
| key | TEXT UNIQUE | `dd_` + 32 位 hex |
| created_at / revoked_at | TEXT | 创建/吊销时间（revoked_at 非空即失效） |

> **迁移**：`db.init_db()` 在建表后检查 `terminals` 缺列则 `ALTER TABLE` 补充并用 `randomblob(16)` 回填 `inbox_token`，老库无缝升级。

## 4. WebSocket 协议

端点：`ws(s)://服务器/ws/{终端编码}`。消息均为 JSON 文本帧。

### 连接建立

1. 服务器校验编码：不存在 → 先发 `rejected` 再以 **4404** 关闭；已注销 → 先发 `rejected` 再以 **4403** 关闭。
2. 校验通过：注册连接（同码多连接并存）、更新 `last_seen_at`、下发 `hello`、仅补发未推送过的消息（`pushed_at IS NULL`，正序逐条标记）。

### 服务器 → 客户端

| type | 载荷 | 说明 |
|------|------|------|
| `hello` | `{code, name, unread, inbox_url, inbox_token}` | 握手：当前未读数与消息中心地址/令牌（客户端持久化 inbox_token，令牌即身份凭据之一） |
| `message` | `data: {id, title, content, sender, url, created_at, pushed_at, read}` | 一条消息；`url` 为消息中心链接（含 `&m=id` 定位） |
| `messages` | `{items: [data...]}` | 响应 `list` 请求，最近 200 条未删除消息 |
| `unread` | `{count}` | 最新未读数（网页已读/删除后推送，客户端更新托盘角标） |
| `heartbeat` | `{server_time}` | 心跳应答 |
| `rejected` | `{reason: "not_found"\|"revoked"}` | 连接被拒（随后连接关闭，客户端停止重连并提示重新注册） |

### 客户端 → 服务器

| type | 载荷 | 说明 |
|------|------|------|
| `heartbeat` | — | 每 30 秒一次，服务器刷新 `last_seen_at` |
| `list` | — | 请求收件箱列表 |
| `read` | `{message_id}` | 标记已读（仅当未读时写入 `read_at`），响应推送 `unread` |
| `delete` | `{message_id}` | 软删除（写入 `deleted_at`），响应推送 `unread` |

## 5. HTTP API 全量参考

鉴权方式：推送接口用请求头 `X-API-Key`；管理接口用 `Authorization: Bearer <token>`；消息中心接口用查询参数 `token`（inbox_token）。无特殊说明均为 JSON 请求/响应。

### 5.1 公共接口（routes_public.py）

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | `/api/terminals/register` | 无 | 注册终端。请求 `{name}`（1–50 字）→ `{code, name, inbox_token}` |
| POST | `/api/terminals/login` | 无 | 登录已有终端（换机重登）。请求 `{code, name}`（名称需与注册一致）→ `{code, name, inbox_token}`；编码不存在 404、已注销/名称不匹配 403 |
| POST | `/api/terminals/unregister` | inbox_token | 客户端自助注销。请求 `{code, token}` → `{ok:true}`；注销后踢断 WS 连接 |
| POST | `/api/messages` | X-API-Key | 推送消息（详见接入文档）。请求 `{terminal_code \| terminal_codes[], title, content, sender}` → `{total, delivered, results[]}`；每终端一个回执，`delivered:false` 表示已入库待补发 |
| GET | `/api/health` | 无 | 健康检查 |

### 5.2 管理接口（routes_admin.py，前缀 `/api/admin`）

> 角色说明：`admin`（管理员）可访问全部接口；`oper`（操作员，config.json 的 `oper_password` 登录）仅能访问 `/push`，其余接口返回 403。下表「🔒」表示仅管理员。

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/login` | `{password}` → `{token, role}`（role=admin/oper；内存会话 12 小时，服务重启失效） |
| GET | `/overview` | 统计：有效终端数/在线数/今日消息/未读数/待补发数 |
| GET | `/terminals?status=&page=&page_size=` | 终端分页列表（含 `online` 在线状态、`inbox_token`） |
| POST | `/terminals` | 手动创建终端 `{name}` |
| POST | `/terminals/{id}/revoke` | 手动注销并踢断连接 |
| POST | `/terminals/{id}/restore` | 恢复已注销终端（刷新 last_seen_at） |
| GET | `/messages?terminal_id=&read=&page=&page_size=` | 🔒 消息记录（read 取 `unread`/`read`；行含 `access_token` 供「查看」全文页） |
| POST | `/messages/batch-delete` | 🔒 批量物理删除 `{ids:[...]}` → `{deleted:n}`（不可恢复，消息中心同步消失） |
| GET | `/apikeys` | 密钥列表（含已吊销） |
| POST | `/apikeys` | 创建密钥 `{name}` → 返回完整 key（`dd_` 前缀） |
| POST | `/apikeys/{id}/revoke` | 吊销密钥 |
| POST | `/push` | 后台直接推送（复用推送逻辑，sender 默认「管理后台」）；**操作员唯一可用接口** |

### 5.3 消息中心接口（page_inbox.py）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/t/{code}?token=` | 消息中心页面（HTML，已读/未读分组折叠 + 历史分页，ES5 兼容旧浏览器） |
| GET | `/api/inbox/{code}/messages?token=&before_id=&limit=` | 收件箱 JSON：`{items, unread, has_more, revoked}`；`before_id` 分页（每页默认 50，上限 100），首页含全部未删除消息 |
| POST | `/api/inbox/{code}/read/{message_id}?token=` | 标记已读（幂等），并向在线客户端同步 `unread` |
| POST | `/api/inbox/{code}/delete/{message_id}?token=` | 软删除，同样同步 `unread` |

### 5.4 页面与下载（page_message.py / main.py）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/m/{id}?token=` | 单条消息全文页（token=access_token；打开即标记已读；管理后台「查看」使用） |
| GET | `/` | 官网介绍页（构建产物 `server/static/site.html`） |
| GET | `/admin` | 管理后台 SPA（Vue 构建产物，Hash 路由；隐蔽入口=官网页脚邮戳） |
| GET | `/download/DingDongSetup.exe` | 客户端安装包（在 `server/downloads/`） |
| GET | `/download/dingdong-api-doc.md` | 第三方接入文档（映射 `docs/第三方接入文档.md`，下载名为中文） |
| GET | `/api/download/info` | 安装包元信息 `{available, filename, version, size_text, updated_at}`（version 来自打包时写入的 version.txt） |
| GET | `/api/docs` | OpenAPI/Swagger 交互文档 |

## 6. 消息生命周期

```
接口入库 ──> WS 送达 ──> 用户阅读 ──> 用户删除（软删）
created_at   pushed_at   read_at      deleted_at
```

- **入库**：`POST /api/messages` 校验 API Key 与参数后写入，`created_at` 记录；终端在线则立即下发并写 `pushed_at`。
- **送达**：离线消息在终端连上后补发（`deliver_pending`，正序、补记 `pushed_at`）。
- **已读**：三个入口均可触发（仅首次生效）：打开 `/m/{id}` 全文页、消息中心点开消息、客户端 WS `read` 上报。
- **删除**：软删除——收件箱/补发不再包含该消息，管理后台仍可审计。
- 待补发数（`pushed_at IS NULL`）在管理后台「总览」可见。

## 7. 终端生命周期

```
注册(active) ──连接/心跳──> 保持 active
     │
     ├── 手动注销(管理后台) ──> revoked ──恢复──> active
     ├── 自助注销(客户端, 凭 inbox_token) ──> revoked（不可自助恢复，需管理员或重新注册）
     └── 30 天未连接(自动任务) ──> revoked
```

- 在线判定：当前存在 WS 连接（`ConnectionManager.active`）。
- 自动注销任务：随服务启动，每小时执行一次；天数由 `config.json: terminal_offline_days` 控制。
- 客户端收到 `rejected`/4403/4404 后停止重连，提示重新注册（本地注册信息清空，服务器地址保留）。
- 注销不会删除历史消息与编码；编码不可复用。

## 8. 安全模型

| 凭据 | 形态 | 作用域 | 失效方式 |
|------|------|--------|----------|
| 管理密码 | config.json 明文配置 | 登录管理后台 | 修改配置重启；建议生产改强密码并由 Nginx 侧加 IP 白名单/HTTPS |
| 管理会话 token | 内存（服务重启即失效，12h 过期） | /api/admin/* | 自然过期/重启 |
| API Key | 数据库存储（`dd_`+32hex） | POST /api/messages | 后台吊销 |
| inbox_token | 数据库存储（32hex），随 WS `hello` 下发并由客户端持久化 | 某终端的收件箱读写/自助注销 | 重新注册产生新终端新令牌（旧终端注销） |
| access_token | 每条消息随机 32hex | 仅 `/m/{id}` 全文页 | 随消息存在 |

设计取舍（内网定位）：API Key 明文存储便于后台复查；令牌均为 128 位随机数防猜测；未做 HTTPS 时凭据在内网明文传输，跨网段/不可信网络请在 Nginx 启用 TLS。注册接口无鉴权（内网自助注册），如需收紧可加 IP 白名单。

## 10. 客户端（Windows）架构

工程：`client/DingDong/DingDong.csproj`，目标 `net6.0-windows`，SDK 风格 csproj，self-contained 单文件发布（约 66MB），目标机器无需安装 .NET 运行时；NuGet 依赖仅 System.Speech。

```
App.xaml(.cs)        单实例 Mutex、--minimized 静默启动、全局异常(error.log)、退出时保存设置
MainWindow           注册/登录双模式向导（编码+名称登录，换机保留编号）/ 终端状态卡（编码·名称·连接胶囊·未读数·复制编码·退出登录·注销）/ 设置卡（服务器地址+端口）
NotifyWindow         右下角弹窗：淡入淡出、自动堆叠(≤4)、悬停暂存、10s 自动关闭、点击打开消息中心
Models/              Settings（含 InboxToken）、Message（INotifyPropertyChanged）
Services/
  WsClient           ClientWebSocket 封装：30s 心跳、断线退避重连 1s→60s、
                     事件 StatusChanged/HelloReceived/UnreadChanged/MessageReceived（均回 UI 线程）
  SettingsStore      %AppData%\DingDong\settings.json 读写（自研 Json 序列化）
  ApiClient          注册 / 登录（编码+名称校验）/ 自助注销 HTTP 调用
  NotifyManager      提示音(嵌入资源 ding.wav)、TTS 调度、弹窗堆叠管理
  TtsService         SpeechSynthesizer 朗读标题或标题+摘要（可中断）
  Browser            打开网页：优先探测三个标准路径下的 chrome.exe，回退默认浏览器
  Json               极简 JSON 序列化/反序列化（避免引入 Web.Extensions）
```

行为要点：注册信息持久化本地、重启自动重连；「退出登录」仅断开本机（保留编码与名称，可换电脑登录，同码多连接并存、推送广播）；「注销终端」编号作废回注册界面；服务器地址/端口在设置卡可改（保存自动重连）；收到消息 = 提示音（可关）+ TTS（可关）+ 弹窗 + 托盘角标（hello/unread/message 事件共同维护未读数）；消息查看/已读/删除全部在网页消息中心完成；应用图标为品牌铃铛（`make_icon.py` 生成，与网页 favicon 同源）。

## 11. 管理后台与官网

- **管理后台**（`web/`，Vue 3 + Element Plus + Hash 路由）：登录（管理员/操作员双角色，操作员仅见「发送消息」）/ 总览统计 / 终端管理（含消息中心直达）/ 消息记录（筛选+批量删除+全文页）/ API 密钥 / 发送消息。构建：`npm run build` 输出至 `server/static/`，由 `/admin` 提供；开发模式 `npm run dev`（5173，已代理 `/api`、`/ws`）。
- **官网**（`web/site.html` 源文件，Vite 多页构建随管理后台输出到 `server/static/site.html`，单文件、无外部依赖、离线可用）：系统介绍（信笺邮政风）、功能票据、客户端下载（实时读取 `/api/download/info` 展示版本/大小/日期）、四份教程、接口文档摘要与完整文档下载；**页脚邮戳为管理后台隐蔽入口**。
- **打包链路**：`client/make_installer.bat` = dotnet publish（自包含单文件）→ Inno Setup（中文界面、当前用户安装、无需运行时检测）→ 输出 `server/downloads/DingDongSetup.exe` + `version.txt`。

## 13. 运维与扩展指引

**日常运维**

- 备份：停服复制 `dingdong.db`，或 `sqlite3 dingdong.db ".backup 'backup.db'"`
- 升级：覆盖代码 → `deploy/service.bat restart`；前端有改动再构建
- 日志：uvicorn 控制台/NSSM `server/logs/`；客户端 `%AppData%\DingDong\error.log`

**常见扩展点**

| 需求 | 改动位置 |
|------|----------|
| 消息加"级别/链接"字段 | `schemas.py`（MessagePushRequest）→ `db.py` 建表加列 + `ws.py` payload → 客户端 Message 模型 → 弹窗样式 |
| 轮换 inbox_token | 管理接口新增一条 `UPDATE terminals SET inbox_token=...` + 客户端 hello 已支持热更新落盘 |
| 推送结果回调第三方 | `routes_public.push_messages` 入库后按 message_id 异步回调 |
| 消息定时发送 | 增加 `scheduled_at` 列 + 后台任务到点调 `deliver_message` |
| 更多角色/操作审计 | security.py 已支持 admin/oper 双角色，可扩展 roles 字典；审计需新增 logs 表 |

**已知边界**：管理会话在内存（重启需重登录）；API Key 明文存储；注册接口无鉴权；单实例单库（SQLite 写并发足够百级终端规模，更大规模建议换 PostgreSQL）。
