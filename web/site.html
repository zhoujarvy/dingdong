编号 004 / TUTORIAL

使用教程

—— 四封指导函，按序投递

准备环境

服务器需安装 Python 3.8+（推荐 3.8），Windows / Linux 均可。项目目录下 server/ 即服务端全部内容。

Python 3.8pip

安装依赖并启动

建议使用虚拟环境；默认监听 8000 端口，数据库为目录下自动创建的 SQLite 文件。

cd server
python -m venv venv
venv\Scripts\pip install -r requirements.txt
venv\Scripts\python run.py # 或直接运行 start.bat

修改管理密码

编辑 server/config.json 中的 admin_password，生产环境务必先改默认密码。

（可选）生产部署

Web 前端推荐 Nginx 反向代理并托管静态资源，后端用 NSSM 注册为 Windows 服务开机自启；参考项目 deploy/部署说明.md。

下载并安装

从本页下载 DingDongSetup.exe，双击安装（当前用户模式，无需管理员权限）。运行时已内嵌，无需安装 .NET。

注册终端

首次运行填写服务器地址（如 http://192.168.1.10:8000）与终端名称，点击「注册终端」，获得 6 位终端编码。注册信息保存在本机，重启电脑自动重连。

接收消息

程序常驻系统托盘：来消息时提示音 + 右下角弹窗（可选语音朗读），托盘图标红底数字显示未读条数。双击托盘或点击弹窗打开网页消息中心。

个性设置

主面板可开关提示音、语音朗读、朗读内容（仅标题 / 标题+摘要）、开机自启；也可注销终端后重新注册。

打开后台

在服务器地址后访问 /admin（入口较隐蔽——就在本页页脚的邮戳上），输入管理密码登录。

管理终端

「终端管理」页查看在线状态、最近连接时间，可手动新建/注销/恢复终端，点击「消息中心」可直接查看某终端的消息。

发放 API 密钥

「API 密钥」页为业务系统创建密钥（可随时吊销）；「发送消息」页可向任意终端直接推送测试消息。

审计消息

「消息记录」页按终端/已读状态筛选，完整呈现创建、送达、阅读、删除全链路时间。

申请密钥

请管理员在后台「API 密钥」页创建一枚密钥，格式形如 dd_3f2a…，等同于推送权限，请妥善保管。

调用推送接口

一个 POST 即可推送；terminal_code 换成 terminal_codes 数组即群发。

curl -X POST http://服务器IP:8000/api/messages \
  -H "Content-Type: application/json" \
  -H "X-API-Key: dd_你的密钥" \
  -d '{"terminal_code":"A2B3C4","title":"工单提醒","content":"新的紧急工单待处理","sender":"OA系统"}'

阅读回执

响应中的 delivered 表示是否实时送达；false 并非失败——终端上线后自动补发，无需重发。

更多示例

Python / C# / JavaScript 完整示例与错误码说明，见接口文档或下载完整文档。

编号 005 / OPEN API

接口文档

—— 一纸电文，四海皆可达

POST /api/messages · 请求字段
字段类型说明
terminal_codestring单个终端编码（与 codes 二选一）
terminal_codesstring[]终端编码数组，一条消息群发
titlestring标题，1–200 字，弹窗与朗读优先展示
contentstring内容，纯文本 ≤ 20000 字，支持换行
senderstring发送方名称，建议填业务系统名
200 送达/已入库 401 缺少密钥 403 密钥无效 422 参数错误
# 请求头必须携带 API Key
POST /api/messages HTTP/1.1
Host: 服务器IP:8000
Content-Type: application/json
X-API-Key: dd_3f2a1b…
# 响应：逐终端回执
{
  "total": 2, "delivered": 1,
  "results": [
    {"terminal_code":"A2B3C4", "message_id":101, "delivered":true},
    {"terminal_code":"X9Y8Z7", "message_id":102, "delivered":false,
     "error":"终端不在线，已入库等待补发"}
  ]
}
